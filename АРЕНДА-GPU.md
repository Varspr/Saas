# Аренда GPU и запуск real-режима — пошагово

Это руководство: **где арендовать**, **какие мощности брать**, **как подключить
после покупки**. Вся техническая подготовка в коде уже сделана — на сервере
понадобится по сути одна команда.

---

## 0. Сразу важное уточнение

«Физика через GPU» — небольшое упрощение. По факту на арендованной машине крутятся
два разных типа вычислений:

| Что | На чём считается | Зачем GPU |
|-----|------------------|-----------|
| **AI: фото → 3D-меш одежды** (SAM + InstantMesh) | **GPU** | да, обязательно |
| **Физика ткани** (Blender cloth) | **CPU** | нет, но запускается на той же машине |
| Рендер превью (Blender Cycles) | CPU или GPU | опционально |

То есть GPU нужен ради превращения фотографии в настоящий 3D-объект одежды.
Физика ткани поедет на процессоре этой же машины. Всё работает вместе в одном
контейнере-воркере.

---

## 1. Какие мощности брать

| Ресурс | Минимум | Комфортно | Почему |
|--------|---------|-----------|--------|
| **Видеопамять (VRAM)** | **24 ГБ** | 24–48 ГБ | InstantMesh + zero123plus занимают ~16–24 ГБ |
| GPU-модель | RTX 4090 / L4 / A10 | RTX 4090 / L40S / A100 | 4090 — лучший баланс цена/скорость |
| Системная RAM | 16 ГБ | 32 ГБ | Blender cloth/Cycles на CPU |
| vCPU | 8 | 12–16 | физика и рендер — на CPU |
| Диск | 60 ГБ | 100 ГБ | образ ~15 ГБ + веса ~13 ГБ + рабочие файлы |

**Вывод по GPU:** бери карту с **24 ГБ VRAM**. **RTX 4090** — оптимально по
деньгам. **A100** — если хочешь скорость/запас или несколько задач параллельно
(но дороже в ~3–4 раза). Меньше 16 ГБ (RTX 3060/T4 16 ГБ) — рискованно, InstantMesh
может не влезть.

Скорость одной примерки на 4090: ориентир 1.5–3 минуты (SAM + InstantMesh +
Blender), как в плане.

---

## 2. Где арендовать

Цены — ориентир (меняются, проверяй на сайте провайдера).

| Провайдер | Что это | RTX 4090 | A100 | Кому подходит |
|-----------|---------|----------|------|---------------|
| **RunPod** (runpod.io) | контейнеры (Pods) + serverless | ~$0.34–0.69/ч | ~$1.2–2.5/ч | **рекомендую для старта**: дёшево, network volume для весов, готов к нашему образу |
| **Vast.ai** (vast.ai) | маркетплейс чужих GPU | ~$0.25–0.50/ч | ~$0.8–1.5/ч | **самый дешёвый** для экспериментов; надёжность ниже |
| **Lambda** (lambdalabs.com) | полноценные Ubuntu-VM | A10 ~$0.75/ч | ~$1.29/ч | **если хочешь весь стек одной командой** (есть root + ssh) |
| **Modal** (modal.com) | serverless, scale-to-zero | — | ~$2.1/ч, но по секундам | **прод с редкими запросами**: платишь только за время обработки |
| Paperspace / CoreWeave | VM/кластеры | разное | разное | если перерастёшь предыдущие |

---

## 3. Что выбрать под твою ситуацию

- **Первый запуск, «посмотреть как работает по-настоящему»** →
  **RunPod, Pod с RTX 4090** (Путь Б ниже). Дёшево, быстро, веса кладутся на volume.
- **Хочу весь сайт (api+воркер+бд+фронт) одной командой на одной машине** →
  **Lambda Labs, VM с A10/A100** (Путь А). Это настоящая Ubuntu-машина, где
  `docker compose up` просто работает.
- **Минимальная цена за эксперимент** → **Vast.ai, 4090** (как Путь А/Б).
- **Продакшен, запросы редкие/неравномерные** → **Modal** (Путь В): GPU
  поднимается на время задачи и гаснет, платишь по секундам.

## 4. Как подключить после покупки

### Путь А — GPU-VM (Lambda / Vast / любая Ubuntu-машина с root)

Самый простой для «всё на одной машине». На сервере по ssh:

```bash
# 1. проверить, что GPU виден
nvidia-smi

# 2. забрать код
git clone <ваш-репозиторий> saas && cd saas

# 3. настроить окружение
cp .env.gpu.example .env
nano .env      # вписать PUBLIC_API_BASE_URL=http://<ПУБЛИЧНЫЙ_IP>:8000
               # узнать IP:  curl -s ifconfig.me

# 4. одна команда — ставит Docker + nvidia-toolkit и поднимает весь стек
bash deploy/gpu_vm_bootstrap.sh
```

Первый запуск долгий (собирается образ ~15 ГБ и качаются веса ~13 ГБ) —
**15–40 минут**. Дальше — быстро.

Логи и проверка:
```bash
docker compose logs -f worker     # видно скачивание весов и обработку
docker compose -f docker-compose.yml -f docker-compose.gpu.yml \
    exec worker python /opt/app/scripts/gpu_check.py
```

Открыть: `http://<IP>:3000` (сайт) и `http://<IP>:8000/docs` (API).

### Путь Б — RunPod Pod (один контейнер-воркер)

RunPod запускает один контейнер. Тогда воркер крутится на GPU, а redis/postgres
лучше взять managed (RunPod их не даёт) — либо для теста собрать всё в образ.
Простой вариант для теста:

1. Сначала собрать образ в CI (workflow уже готов: `.github/workflows/gpu-worker.yml`)
   → он попадёт в `ghcr.io/<owner>/<repo>/worker-gpu`. Сделай пакет public
   (или добавь registry-креды в RunPod).
2. На runpod.io → **Deploy a Pod** → GPU **RTX 4090** (или A100).
3. **Container Image**: `ghcr.io/<owner>/<repo>/worker-gpu:latest`.
4. **Volume**: примонтировать в `/models` (чтобы веса качались один раз).
5. **Environment variables** (вкладка Environment):
   ```
   MOCK_PIPELINE=false
   DRAPE_BACKEND=blender
   REDIS_URL=redis://<managed-redis-host>:6379/0
   DATABASE_URL=postgresql+psycopg://<user>:<pass>@<managed-pg-host>:5432/tryon
   USE_LOCAL_STORAGE=false
   S3_ENDPOINT_URL=...   S3_BUCKET=...   S3_ACCESS_KEY_ID=...   S3_SECRET_ACCESS_KEY=...
   PREWARM_INSTANTMESH=true
   ```
6. Запустить. Воркер сам подтянется к Redis/Postgres/S3.

API (`Dockerfile.api`), Redis и Postgres держи отдельно (дёшево, CPU): managed-
сервисы (например, Upstash Redis + Neon/Supabase Postgres + Cloudflare R2) или
маленькая CPU-VM с `docker compose up api redis db`.

```
[CPU: managed/маленькая VM]        [GPU: RunPod Pod]
  api + redis + postgres + S3  ⇄  worker (наш GPU-образ)
        ▲                                │
   браузер/фронт                  тянет задания, пишет результат в S3
```

### Путь В — Modal (serverless, по запросу)

Файл уже готов: `backend/deploy/modal_app.py`.

```bash
pip install modal && modal token new
modal secret create tryon-env MOCK_PIPELINE=false DRAPE_BACKEND=blender \
    DATABASE_URL=... REDIS_URL=... USE_LOCAL_STORAGE=false S3_...=...
modal deploy backend/deploy/modal_app.py
```
GPU поднимается на время задачи и гаснет. В `app/api/jobs.py::_enqueue` тогда
вызывается Modal-функция вместо Celery (см. комментарий в modal_app.py).

## 5. Проверка, что всё готово

После старта (Путь А/Б) выполни внутри воркера:
```bash
python /opt/app/scripts/gpu_check.py
```
Должно быть ✅ по: nvidia-smi, torch.cuda, Blender, веса SAM, InstantMesh,
segment_anything. Если ❌ на весах — подожди (они докачиваются) и повтори.

Затем создай задание (ссылка на товар или фото) и дождись `status=done`.
В real-режиме результат — настоящий 3D-меш одежды с физикой на теле.

---

## 6. Доступ к сайту снаружи (порты/firewall)

- Нужны открытые порты **8000** (API) и **3000** (сайт).
- На Lambda/Vast — открой их в Security Group / настройках инстанса.
- На RunPod — «Expose HTTP Ports» 8000/3000 в настройках Pod.
- `PUBLIC_API_BASE_URL` в `.env` должен указывать на публичный IP:8000, иначе
  фронтенд будет стучаться в localhost. После его изменения пересобери фронт:
  `docker compose up -d --build frontend`.

---

## 7. Сколько стоит и как экономить

- 1 задание ≈ **$0.10–0.20** (как в плане): ~2–3 минуты GPU.
- **Не держи GPU включённым в простое.** Варианты:
  - RunPod/Lambda — останавливай Pod/VM, когда не используешь.
  - **Modal** — сам гасит GPU между задачами (платишь только за обработку).
- Постоянно держи только дешёвую CPU-часть (api+redis+db) — она копеечная.

## 8. Чек-лист перед первым реальным прогоном

- [ ] Арендована GPU с **≥24 ГБ VRAM** (рекоменд. RTX 4090)
- [ ] `nvidia-smi` показывает карту
- [ ] `.env` создан из `.env.gpu.example`, заполнен `PUBLIC_API_BASE_URL`
- [ ] `MOCK_PIPELINE=false`, `DRAPE_BACKEND=blender`
- [ ] Стек поднят (Путь А `bootstrap`, или Pod из образа)
- [ ] `gpu_check.py` — все ✅
- [ ] Открыты порты 8000/3000
- [ ] Прогнал 1 товар → `done` → крутится 3D
